# PilarBus.
Repositorio para el caso de estudio 1.
Para entender qué es el pull request, primero tenemos que ver dos cosas. La primera es la Rama Principal (o main), que es la versión oficial de una aplicación y con la que los usuarios interactúan. En segundo lugar, tenemos la Rama de Funcionalidad (feature), que es una copia temporal donde surgen las ideas que ponemos en nuestro tablero para mejorar o cubrir una necesidad en una app para los usuarios. Luego está el pull request, que es la solicitud formal de un desarrollador de unir su código a la rama principal (antes de esto, otros desarrolladores lo prueban y dan su opinión sobre el código y qué se puede mejorar).
​Una vez unido el código, hay dos etapas que debe pasar. La primera es la Integración Continua (CI), un proceso automatizado que salta cuando subís el código: este compila todo (BUILD) y ejecuta pruebas automáticas (TEST). Por último, está la Entrega Continua (CD); si los TEST dan verde, el sistema aprueba que se despliegue (DEPLOY) en la nube de forma segura.
